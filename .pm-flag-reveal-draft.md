**Workstream:** GeoParty framework extraction · **Date:** 2026-08-23

## 1. The pitch (as PM)

Eduardo's instinct is right: build a second, **structurally-distinct** game before extracting anything. It converts an unanswerable architecture question ("what's the reusable asset?") into an empirical one ("what do we actually reach for when we rebuild?").

**Flag Reveal is a strong candidate** because it breaks the one assumption GeoParty never had to hold: **private, hidden information plus a first-to-buzz arbitration** that no longer forgives slow or simultaneous inputs. GeoParty's interaction model was forgiving — everyone saw the same street, everyone had the same turn to answer. A buzz-in flag game forces the sync engine to answer a question it never faced before.

## 2. The game

A flag is revealed piece-by-piece. Players ring in to guess the country/territory. First correct ring wins the round.

### Core loop
1. TV shows a flag, progressively unveiled (tiles clearing, blur→sharp, silhouette→color).
2. Players watch the TV. When they think they know it, they **ring in** on their phone.
3. A player who rings in gets to answer. Correct = points. Wrong = locked out (or penalty).
4. Faster rings / fewer tiles shown = more points.

### The new concurrency question (why this is the right stress test)
GeoParty never had to arbitrate "who was first." Ring-in with no server code and RTDB last-write-wins is genuinely new:
- **How to resolve simultaneous buzzes fairly?** Two phones ring within the same RTDB write window. There is no single authoritative clock in the current model.
- **Should the TV be the buzzer arbiter?** The TV is the one shared node — but it only *writes* `screenHeartbeat` today; it never arbitrates.
- **Do we accept a ~250ms write-granularity tie and use a deterministic tiebreak?** (e.g., lowest deviceId, or a per-round seeded order) — or does that feel unfair in a family game?

This is exactly the kind of question that tells us whether the framework's write-ownership model generalizes or only survived because GeoGuess was forgiving. **[Opus should have taken a hard position here.]**

## 3. Existing party games we could bring in (research)

Genre-relevant couch/phone/TV games found in research:

| Game | Mechanic | Reusable for our framework? |
|---|---|---|
| **Jackbox** (Quiplash, Fibbage, Drawful, Trivia Murder Party) | TV prompt + phone input, writing/drawing/quiz | Core pattern: TV is the board, phones are controllers. Directly the model we build on. |
| **Netflix Party Games** (Boggle Party, Party Crashers, Minigolf) | Boggle-style words, fool-your-friends, physical-ish | Proof the TV+phone party niche is hot; Boggle = word reveal on TV. |
| **Kahoot! / Blooket / Quizizz** | Live host + players answer on phones, PIN join, speed scoring | Ring/answer arbitration + real-time scoreboard — **the closest analog to our new concurrency problem.** |
| **GeoGuessr / Seterra** | Map + flag/capital quiz, solo and Seterra-class flag quizzes | Our own reference; flag data + difficulty tiers. |
| **Guess the Image / Picture Reveal** (apps, Classtools) | Progressive tile reveal, guess to get coins | Direct mechanical template for the "fewer tiles = more points" scoring. |
| **Offline no-tech** (Charades, Would-You-Rather, Never-Have-I-Ever, 20 Questions, Pictionary) | No screens needed | Cheap to digitize — but no "first-to-buzz" pressure; weaker framework signal. |

**Recommendation:** The *digitizable no-tech party classics* (Pictionary/20 Questions/charades) are quick wins but don't stress the framework the way **buzzer/trivia** (Kahoot-style) does. If the framework extraction is the goal, the **first-ring arbitration** mechanic — which the flag game forces — is the highest-signal thing to build first.

## 5. Datasets to base games on

### Flags (primary — for Flag Reveal)
| Source | License | Notes | Pick? |
|---|---|---|---|
| **lipis/flag-icons** (12.4k ★, MIT) | MIT | Per-country SVG (`flags/1x1`, `flags/4x3`), ISO 3166 alpha-2 filenames, actively maintained. | ✅ **Best default** — MIT, clean SVGs, easy to bundle as static assets. |
| **hampusborgos/country-flags** (3.8k ★) | per-flag | SVG+PNG, accurate, includes territories; licensing varies per flag. | ✅ Strong alternative, slightly more work on attribution. |
| **iso3166-flags** (amckenna41) | SVG | Verbose ISO 3166-1/-2 incl. subdivisions. | Good for hard/extended modes. |

### Geography/trivia (for sibling games)
- **Open Trivia DB** (opentdb.com) — free JSON API, no key, thousands of questions across categories. Can be fetched once and bundled as static JSON (offline-friendly).
- **Rest Countries** / **Country data** APIs — capitals, flags, codes, names for building our own question set.
- **GeoGuessr/Seterris** — the domain we already own; flags + capitals + cities as difficulty tiers.

**Bundle strategy:** static JSON + bundled SVG/PNG assets, served same as GeoGuess — no build step, works offline / file://. Matches the no-server constraint.

## 7. Framework-extraction lens (the experiment's point)

- **REUSES (likely stable):** phase machines, write ownership (host = sole writer in couch), ≤4/s throttle, clock discipline (`endsAt − now`), deadlock guard pattern.
- **MUST REWRITE (the test):** the buzzer/ring arbitration — first-write-wins across phones with no server clock. This is the part of the "party-room kernel" that GeoGuess never exercised.
- **Danger signal to watch:** if the flag game's sync has to fight the existing write-ownership model (e.g., the ring needs its own arbitration node), the extraction hypothesis weakens. If it slots in cleanly (a small `ring.js` pure module + a well-fenced write path), the framework hypothesis is confirmed.

## 8. What's next / decisions needed

1. **Approve Flag Reveal as the first "proof game."** (vs. a Kahoot-style trivia game, which tests the same buzzer.)
2. **Pin the ring arbitration design** — Opus's take on fair buzz resolution with RTDB constraints. This is the load-bearing decision.
3. **Pick dataset** (default: lipis/flag-icons, MIT).
4. **Scope the build** (one game, written from the design not copy-paste, tests + instrumentation, static/no-build).
5. **The writeup as demand probe** (in parallel, near-zero cost).

## 6. Honest risks
- **Ring-in fairness is hard** — if it feels unfair, a family game dies. We may need to accept deterministic tie-breaks that feel arbitrary to players.
- **Same-shape risk** — if we keep choosing geography/puzzle games, we never learn the seam. Flag Reveal is chosen precisely to break shape.
- **Budget/sunk-cost** — one game is the commitment; the third game is where momentum, not evidence, takes over.
